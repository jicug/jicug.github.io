- Connpassのグループに参加することでJICUGメンバーとして発信・登壇が可能

### IBM Champion Japan Forum 2026 ハッカソン概要

- 開催場所：天城ホームステッド（IBMの施設）
- 開催日：2026年8月3日〜4日
- 全国から35名のIBMチャンピオンが参加

### テーマ1：IBM WatsonX Code Assistant（Bob IDE）でフロントエンドを作成（田中正吾）

- 担当：フリーランスエンジニア・田中正吾氏（屋号：ワンフットシーバス）
- 作成アプリ：伊豆観光サポートアプリ（GPS連動ポイント収集・クーポンガチャ・ARナビ機能）
- Bob IDEを活用してHTMLスクロール型のプレゼンスライドを生成（PowerPointではなくHTMLが有効と判断）
- GitHub Codespaceを使ってデモを実施し、ある程度動作を確認
- 開発経緯をDocsフォルダ内のNotesに逐次記録し、Gitログと組み合わせてBobに振り返りをさせることができた
- サウンドシステム・コインポイント・ARカメラ実装で苦戦したが、Bobとのディスカッションで解決
- 主な苦戦ポイント：
  - オーディオのPromise Rejectエラー
  - BGMが2重再生されて爆音になる問題
  - ARカメラストリームの遅延
- 経緯ログを定期的に残すことで、設計の再構築時にも対応しやすくなると実感
- コミットはBobに自動でさせず、人間側が仕切ることでサクサク進行できた

### テーマ2：伊豆スタンプラリーの開発過程（鹿野市郎）

- 担当：鹿野市郎氏（IBMチャンピオン、プログラミング講師等も兼務）
- 作成アプリ：伊豆スタンプラリー（観光地のQRコードを集めてスタンプを押し、ランキングを競うWebアプリ）
- ブレインストーミングでポストイットにアイデアを大量出しし、分類・整理をAIに丸投げする手法を採用
  - 隣チームはホワイトボードの写真をそのままAIに読み込ませており、手入力の手間を省いていた
- Bobに対し「疑問があれば人間に質問してね」と指示することで、不足要件を自動的に洗い出させた
  - ゲーム参加方式・ユーザー認証方式・技術スタック等をBobが質問し、人間が選択する形で仕様を確定
- 技術スタック：Node.js、SQLite、WebSocket、QRコード、コンテナ（Docker）
- BootstrapのCSSを指定してWebサイトを自動生成（画像のみ他ツールで作成）
- イベント参加者がスマホでQRコードを読み取り、実際にスタンプラリーをリアルタイムでデモ実施
- 推奨する開発手順：
  - **やらない方がいいこと**：とりあえず作って後から改善（バグ・複雑化・手戻りが多発）
  - **やった方がいいこと**：要件定義・設計書をしっかり作ってからアプリ生成（バグが少なく一気に完成）

### テーマ3：伊豆エクスプローラーの開発過程（西川浩平）

- 担当：大学教員・西川浩平氏（病院・学校・教育委員会向けシステム開発も担当）
- 鹿野氏と同じチームで、2パターンのアプリを並行して開発
- 作成アプリ：伊豆エクスプローラー（観光ルート提案・食べ歩き・お土産レコメンド・スタンプラリー・管理画面を含む総合観光アプリ）
- ブレストの内容をMarkdownファイルにまとめBobに渡し、アーキテクチャを決め打ちで指示
  - 技術スタック：Node.js 24（LTS）、SQLite3、OpenStreetMap、Docker Compose
- Bobにプランファイル（設計書）を生成させ、内容を確認・微調整してからコード生成を指示
  - プランファイルにAPIエンドポイント・画面構成・テーブル設計・依存パッケージ等を含めた
  - 設計書をしっかり作ったことでほぼエラーなく動作するアプリが完成
- 夜にBobを走らせて放置し、翌朝バグ取りして完成させるという効率的な開発フローを実践
- ユーザー認証はセッションIDとSQLiteの組み合わせで対応（ログイン機能は時間の都合で省略）
- お土産・食べ歩きレコメンド機能にはOpenAI（GPT-4o）のAPIを組み込み（WatsonXにすべきだったと反省）
- Docker Composeで全サービスを一括起動できる構成に整備

### Ask the speaker・雑談（鹿野市郎による追加発表）

- ハッカソンでの経験を活かし、アプリ内にAIを組み込む「AI社員」アプリを自作

  - バージョン1.0：グリッド取引ロジックを人間が手作業でチューニング
  - バージョン2.0：OpenAIが取引履歴を定期的に振り返り、パラメーターを自動更新
- 取引自体は微増益だったが、相場の大暴落により損失が発生
- AIを組み込んだアプリが2日程度で作れる時代になったことを実感
- 次回はBobを使ってAI社員第2弾を作成予定
- 「好きな趣味に本気で使えるアプリを作ると楽しい」とコメント

## オープニング・JICUGとイベント概要の紹介

- 田中正吾がMCとしてイベントを開始し、JICUG（ジャパンIBMクラウドユーザーグループ）の概要を紹介した。JICUGはIBMクラウドを活用する日本のユーザーが運営するコミュニティで、現在リブート中である。
- JICUGは契約プランや活用方法を問わず、IBMクラウドに興味がある人や業務で使用している人であれば誰でも参加可能とされている。
- connpassのグループに参加することでJICUGメンバーとして発信でき、LT登壇や長めの発表も気軽に応募できると案内された。
- 今回のイベントの中心は、天城ホームステッドで開催されたIBMチャンピオンジャパンフォーラム2026のハッカソン体験の共有であり、全国から35名のIBMチャンピオンが参加した。
- ハッカソンのテーマは「伊豆の観光ビジネスを稼げるアプリ」で、6チームに分かれ前半80分・後半45分の超高速ワークショップ形式で行われた。
- 登壇者は田中正吾（BOM IDEでのフロントエンド開発）、鹿野市郎（伊豆スタンプラリーの開発過程）、西川浩平（伊豆エクスプローラーの開発過程）の3名。
- ハッカソンの目的はアプリ開発だけでなく参加者同士の親睦を深めることであり、ポストイットやホワイトボードを使ったブレスト、IBM Bobとの壁打ちなども行われた。



## 田中正吾：Bob IDEでフロントエンドアプリを開発した体験談

- 田中正吾はフリーランスエンジニア（屋号：ワンフットシーバス）として、ウェブフロントエンドをベースに生成AI・IoT・XRなどを取り入れた開発を行っている人物である。
- ハッカソンでは伊豆観光客向けのサポートアプリを開発し、GPS連動のポイント収集機能、クーポンガチャ、ARによる方角表示などを実装した。
- IBM Bobを使ってHTMLスクロール型のプレゼンテーションスライドを作成し、PowerPointではなくHTML形式で発表資料を作る方法が効果的だったと報告した。
- GitHub Codespaceを使ってデモを行い、音楽再生・ARカメラ・GPS取得などの機能が短時間にもかかわらずある程度動作することを確認した。
- 開発経緯をDocsフォルダのNotesに逐次記録し、GitログとNotesをBobに読み込ませることで開発の振り返りや苦戦ポイントを後からリアルタイムで再現できた。
- サウンドシステム（BGMの2重鳴り・autoplay）、ARカメラのストリーム遅延、コインポイントの加算タイミングなど複数の技術的課題をBobと協力して解決した。
- 経緯ログを定期的に人間が手動で切り替えることで約8本のまとまったノートが作成でき、設計の再構築が必要な場面でも履歴を活用できる仕組みを構築したと総括した。



## 鹿野市郎：伊豆スタンプラリーアプリの開発過程とAI活用の知見

- 鹿野市郎はサーバーグローバル製造技術・クラウドマネジメントサービス担当であり、個人活動としてITサービス副業や子ども向けプログラミング教室講師なども行っている。
- ハッカソンでは6人チームで議論し、エンジニアが多いため「儲かるアプリ」というテーマで活発なブレストが進み、アイデアが大量に出た一方で時間内の整理が追いつかなかった。
- 時間不足を逆手に取り、ブレスト結果のポストイット内容をそのままIBM Bobに丸投げし、分類・グルーピングのステップをAIにスキップさせるというアプローチを採用した。
- Bobにアプリ開発前に「疑問があれば人間に質問してね」と指示することで、ゲーム参加方式・ユーザー認証方法・技術スタック（Node.js・SQLite・WebSocket・Docker）などの仕様を対話形式で決定した。
- 完成したプログラムのソースコードをBobに読み込ませてWebサイトを自動生成させ、Bootstrapを使ったデザインのランディングページが短時間で完成した（画像生成は他AIを使用）。
- 発表ではアプリのデモをリアルタイムで行い、参加者がQRコードをスキャンして観光地スタンプを集め、ランキングや次の行き先投票機能を実際に体験した。
- 「まず設計書をしっかり作ってからアプリ開発する」ことの重要性を強調し、後からの変更や修正が激減してバグの少ない完成度の高いアプリが一気に作れると結論づけた。



## 西川浩平：伊豆エクスプローラーの開発過程とプランファイルの重要性

- 西川浩平は大学教員であり、病院・学校関係のシステム開発や教育委員会へのRFP監修なども行っており、元々は日本IBMグループのグループ会社に在籍していた経験を持つ。
- 鹿野さんと同じチームで意図せず2パターンのアプリを並行開発することになり、西川が担当したのが「伊豆エクスプローラー」である。
- ブレスト結果のMarkdownファイルをBobに渡し、アーキテクチャ（Node.js 24・SQLite3・オープンストリートマップ・Docker Compose）を自分の経験から決め打ちした上でプランファイル（設計書）を作成した。
- プランファイルをBobに夜7時頃に渡して走らせ、翌朝には主要な機能がほぼエラーなく出来上がっており、朝にバグ取りと動作確認を行うという効率的な開発フローを実現した。
- アプリには観光地スタンプラリー機能・バッジ取得機能・管理画面・食べ歩きプラン生成・お土産レコメンドが含まれており、AIバックエンドにはOpenAI（GPT-4o）のAPIを利用した（WatsonXを使えなかったことを後悔）。
- セッションIDとSQLiteデータベースを組み合わせてログインなしでユーザー状態を維持する仕組みを採用し、ハッカソンの時間制約の中で実用的なアプリを完成させた。
- プランファイルを丁寧に作ることでほぼエラーなく実装できた点を成功要因として挙げ、GitHubのREADMEにまとめて後日リンクを共有する予定とした。



## 鹿野市郎：AI社員アプリ（自動仮想通貨取引システム）の紹介

- ハッカソンで西川のアプリ内にOpenAI APIが組み込まれているのを見て触発され、自身でもAIを内蔵したアプリを開発したと紹介した。
- 「AI社員」と名付けた24時間無人で動作する自動仮想通貨取引アプリを作成し、バージョン1.0では自分でロジック（グリッド取引・上昇/下降トレンド判定）を手作業でチューニングしていた。
- 10万円の初期資金で3か月自動取引を実施したが、1回あたり数円程度の微小な利益しか得られず、仮想通貨の大暴落により損失が利益の10倍以上となった。
- ハッカソンの経験を活かし夏休み中にバージョン2.0へ進化させ、OpenAI（GPT-5.6 Luna）を組み込んでAI自身が取引履歴を分析しパラメーターを自律的に書き換える仕組みを実現した。
- 1時間・3時間・6時間・24時間ごとにプロンプトを投入して過去の取引を振り返り、コスト削減のためAPIコール頻度を制限しながら継続的にパラメーターを最適化する設計になっている。
- 取引所APIとOpenAI APIの2つの外部連携を持ち、JSONで取引履歴を記録して過去のトレンドをAIが学習し続けることで自己進化するエージェント的なアーキテクチャを実現している。
- まだ赤字であるものの「AIを内蔵したアプリが2日程度で作れる時代になった」という驚きを強調し、好きな趣味に本気で使えるアプリを作ることを参加者に勧めた。
